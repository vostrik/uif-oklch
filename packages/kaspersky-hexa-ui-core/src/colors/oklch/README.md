# Цветовые токены на OKLCH (экспериментально)

Все цветовые токены Hexa (`src/colors/tokens-pixso/tokens.css`) выводятся из **одного базового цвета**
`--hx-base` через `oklch(from …)`. Тёмная тема здесь не вторая таблица соответствий, а та же таблица:
светлота каждого шага проходит через одну кривую.

Стенд «было / стало»: https://kasperskylab.github.io/uif/hexa-ui-core-oklch/

```css
@import '@kaspersky/hexa-ui-core/colors/oklch/tokens.css';

/* сменить бренд — один токен */
:root { --hx-base: #00A88E; }
```

Имена переменных те же, что в `colors/tokens.css`, поэтому файл подключается вместо него без правок компонентов.
Нужны relative color syntax и `pow()`/`exp()` в `calc()`: Chrome 122+, Safari 18+, Firefox 128+.

## Модель

| Ось | Формула | Что задаёт |
| --- | --- | --- |
| L | общая шкала `--hx-l-50…900` | одна для всех семейств: контраст шага не зависит от тона |
| C | `c_base · k · e^(−((L − peak) / 0.3)²)` | хрома гаснет к краям шкалы, у семейства свои `k` и `peak` |
| h | `h_base + Δh (+ warm · (L − 0.55))` | семейство — это сдвиг тона; `warm` — «температура» для тёплых цветов |

Тёмная тема:

```
L' = floor + gain · (1 − L)^γ      floor 0.235 · gain 0.86 · γ 0.8
```

Ручная таблица Hexa почти точно ложится на зеркало L относительно ≈ 0.63. γ < 1 дополнительно растягивает
тёмные уровни подложки, как и сделано в оригинале. Хрома не переносится, а пересчитывается по новой L.

Правила, которых нет в формуле:

- **Заливки не темнеют** в тёмной теме: `max(L, L')`. Иначе жёлтый warning становится коричневым.
- **Состояния** — это сдвиг L (`hover` 0.04, `active` 0.12), знак задаёт тема (`--hx-state-dir`).
- **Тени и scrim** не инвертируются.
- **Бренд Kaspersky** (`kaspersky_green_*`) — фиксированные цвета, остаются ручной парой.
- Новые токены `--fg--on_accent|danger|success|warning`: цвет текста выбирается по L заливки.

Вся тёмная тема в коде:

```css
.theme-dark { --hx-dark: 1; --hx-state-dir: 1.3; color-scheme: dark; }
```

## Насколько близко к Hexa

ΔE_OK между оригиналом и генерацией, по всем 436 токенам:

- светлая: в среднем ≈ 1.2, 91% токенов < 3 (на глаз неотличимо);
- тёмная: в среднем ≈ 3.8, медиана ≈ 2.9.

Крупные расхождения в тёмной теме почти все там, где ручная таблица сама нарушает логику переворота
(часть графиков, терминал, `accent_muted`). Стенд показывает их списком.

`--hx-follow: 1` вращает все семейства вместе с базой. Чтобы статусы (danger, warning, success) держали
свой тон при смене бренда, поставьте `--hx-follow: 0`.

## Файлы и команды

- `params.js` — параметры (подобраны МНК по текущим hex-примитивам). Палитра меняется здесь.
- `oklch-build.js` — генератор: читает `tokens-pixso/tokens.css`, пишет `tokens.css` рядом.
- `tokens.css` — сгенерированный файл, руками не править.
- `demo/template.html` — стенд «было / стало».

```shell
npm run build:oklch        # перегенерировать tokens.css
npm run build:oklch-demo   # ещё и стенд в ./oklch-demo/index.html
```

После `npm run update-colors` перегенерируйте и этот файл: тест `oklch-build.test.js` проверяет,
что `tokens.css` актуален и что ни одно имя токена Hexa не потерялось.
